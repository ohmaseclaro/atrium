Remote Chromium your app can share with a human

Atrium is a small stack for human-in-the-loop flows: OAuth, MFA, captchas, or any step where automation should pause while a person uses a real browser session—then hand control back, export cookies, and capture Playwright storageState.

Try the live demo Source on GitHub npm scope @atriumjs

What you get

Host API

Express (and a framework-agnostic core) expose session creation, control transfer, navigation allowlists, cookies, and snapshots over HTTP—your worker dials out; browsers never get raw CDP keys.

Viewer UI

@atriumjs/react renders the remote canvas with optional chrome, tab strip, and toasts for passkey limitations—embed in your product behind your own auth.

Quick start

1. Install

npm install express @atriumjs/express @atriumjs/react @atriumjs/worker
npm install react react-dom
npx playwright install chromium

2. Run the worker

ATRIUM_WORKER_SECRET=replace-me npx atrium-worker

3. Mount the API (Express)

import express from "express";
import { createServer } from "node:http";
import { atrium } from "@atriumjs/express";

const app = express();
const { router, handleViewerUpgrade } = atrium({
  authorize: async (req) => ({ tenantId: "t1", userId: "u1" }),
  policies: { /* sessionTtlMs, urlAllowlist, … */ },
  workerDialBase: process.env.ATRIUM_WORKER_DIAL_BASE!,
  workerSharedSecret: process.env.ATRIUM_WORKER_SECRET!,
  mountPath: "/atrium",
});
app.use("/atrium", router);

const server = createServer(app);
server.on("upgrade", handleViewerUpgrade);
server.listen(3000);

4. Create a session and render the viewer

POST /atrium/sessions returns sessionId, viewerToken, and transport URLs. Pass them into @atriumjs/react—see the quick start doc and user guide for full detail.

Deployment (same VPS pattern as our other apps)

Production uses Cloudflare in front, host nginx on port 80, and no Docker for the marketing HTML or the demo Node process by default. The Playwright worker may run in Docker or directly—see docker/worker/Dockerfile in the repo.

Split hostnames

  • atriumjs.dev — vhost deploy/nginx/atrium-landing-host.conf → root …/deploy/landing (this file).
  • demo.atriumjs.dev — vhost deploy/nginx/atrium-demo-host.conf → proxy_pass to 127.0.0.1:$PORT (Express + Vite-built static UI + WS upgrades).

Server update script

On the VPS, the repo lives under /home/atrium (or $ATRIUM_DEPLOY_DIR). Run: 

cd /home/atrium && ./deploy/update-demo.sh

That script: git fetch/reset → pnpm install --frozen-lockfile → pnpm build → sudo systemctl restart atrium-demo → sync both nginx site files and sudo nginx -t && systemctl reload nginx. Passwordless sudo is required for those commands only—see deploy/README.md.

systemd

deploy/atrium-demo.service runs deploy/run-demo.sh from packages/demo with EnvironmentFile=deploy/atrium-demo.env (PORT, worker dial URL, shared secret).

GitHub Actions

Workflow .github/workflows/deploy-demo.yml runs on pushes to main when demo, libraries, lockfile, or deploy/** change: CI lint/test/build, then SSH (same secrets as our Capitanias deploy: SSH_HOST, SSH_USER, SSH_PRIVATE_KEY) executes the update script and curls /atrium/healthz on loopback.

Docker (optional)

  • Worker image: docker/worker/Dockerfile — publish 7070 (or your dial port) to loopback only.
  • Demo + landing do not require app containers; keep the box aligned with other nginx-terminated projects.

Publish to npm

Maintainer checklist: docs/npm-publishing.md (pnpm publish:check, ordered pnpm publish for protocol → core → express → …).
